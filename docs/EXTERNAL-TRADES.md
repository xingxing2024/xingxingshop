# 外部菜单商店交易登记

本版本新增控制台指令，复用 XingXingShop 交易数据库、交易查询和个人日报，不改变原数据库表结构。

```text
shop record <在线玩家> <来源> <buy|sell> <商品ID> <数量> <总金额> <货币ID> <商品名称> [id=外部ID]
```

`id=外部ID` 是可选参数：同一个 ID 重复调用只会记录一次，用于防止菜单重复触发、重复统计。

捕捉箱示例（价格 800，数量 1）：

```text
shop record AAS TrMenu buy trap_box 1 800 vault 捕捉箱
```

TrMenu 的成功购买分支可添加：

```yaml
- 'console: shop record %player_name% TrMenu buy trap_box 1 800 vault 捕捉箱'
```

必须在确认扣款、发货成功之后调用，不能放在点击事件入口或失败分支。指令只登记，不扣钱、不发货，也不会检测其他插件是否成功。现有菜单按顺序执行 take-money 和 give 并不保证这两步一定成功，需要菜单作者保证成功条件。一次成交只调用一次；重复调用会产生重复交易记录。

1.0.2 另有试验性 TrMenu/NekoTraps 自动识别，详见 AUTO-TRADES.md。同一笔捕捉箱购买只能使用一种登记方式，不能同时使用自动识别和上述手动登记指令，否则会重复统计。

登记后管理员用 /shop log AAS 查看，玩家用 /shop myreport today 查看当日统计。若个人日报在配置中关闭，需要在部署时自行开启。来源保存在 shop_id，例如 external:TrMenu；金额必须使用与个人日报其他交易可比较的货币，现有日报仍合并所有货币金额，没有多币种分别统计。

外部登记拒绝玩家执行（含 OP），允许控制台调用。来源仅支持 1–48 个英文字符、数字、下划线或横线；数量须为正整数、金额须为有限非负数。真实外部交易不会因玩家为 OP 而从日报排除。

其他插件可在主线程完成交易后调用：

```java
ShopPlugin.getInstance().transactionLog().recordExternal(
    player, "OtherShop", "trap_box", "捕捉箱", "vault", true, 1, 800.0);
```

没有自动捕获任意插件内部交易；其他菜单或插件需在成交位置调用此接口或控制台指令。数据库不可用时只保留文本日志和最多 2000 笔内存记录，重启后的日报需要可用数据库才能查询旧记录。此开发未修改服务器菜单、配置或运行状态。
