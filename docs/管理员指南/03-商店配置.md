# 商店配置

商店文件放在 `plugins/XingXingShop/shops/`，**一个分类一个文件**，文件名随便起。

改完执行 `/shop reload` 生效。

## 最小示例

```yaml
id: myshop
name: '我的商店'
icon: CHEST
type: BUY

items:
  bread: 1.5
```

`bread` 就是材质 `BREAD` 的小写，后面直接写单价。`/shop reload` 后就能看到「我的商店」。

如果商品 ID 和材质名不一样，才需要写完整形式：

```yaml
items:
  my_bread:
    material: BREAD
    buy: 1.5
```

## 文件头字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 否 | 商店 ID（命令里用），不写就用文件名 |
| `name` | 否 | GUI 里显示的名字 |
| `icon` | 否 | 主菜单里的图标，默认 CHEST |
| `type` | **是** | `BUY`（购买）或 `SELL`（收购） |
| `desc` | 否 | 主菜单里的说明文字（列表） |
| `permission` | 否 | 打开这个分类需要的权限 |
| `open-from` | 否 | 活动商店开放时间（`2026-10-01 00:00`），不写=立即开放 |
| `open-to` | 否 | 活动商店结束时间，不写=永不结束 |
| `items` | **是** | 商品列表 |

### `type` 说明

| 值 | 菜单类型 | 商品价格字段 |
|---|---|---|
| `BUY` | 玩家花钱**买** | 直接写单价，例如 `bread: 1.5` |
| `SELL` | 玩家**卖**东西换钱 | 直接写单价，例如 `cobblestone: 0.02` |

**写错会导致价格不生效**，这是最常见的配置错误。

## 商品写法

### 写法一：一行一个（推荐）

```yaml
items:
  bread: 1.5
  cooked_beef: 3
  cobblestone: 0.5
```

商品 key 就是**材质名小写**，同时也就是**商品 ID**，命令里用它。

### 写法二：一行 + 选项

需要限量、限购、动态价格时，可以继续写在一行：

```yaml
items:
  diamond: 260 stock=300 limit=16 dynamic=true
  golden_apple: 78 stock=200 limit=3
```

支持的选项：`stock=`、`limit=`、`sell-limit=`、`dynamic=`、`slot=`、`currency=`、`permission=`、`glow=`、`custom-item=`。

### 自定义物品（ItemsAdder / Nexo / MMOItems）

如果服务器装了自定义物品插件，商品可以直接写对应物品：

```yaml
items:
  ruby:
    custom-item: itemsadder:myitems:ruby
    buy: 100

  magic_sword:
    custom-item: nexo:magic_sword
    buy: 500
    stock: 10

  legendary_blade:
    custom-item: mmoitems:SWORD:LEGENDARY_BLADE
    buy: 2000
    limit: 1
```

格式：

| 来源 | 写法 |
|---|---|
| ItemsAdder | `itemsadder:命名空间:物品ID` |
| Nexo | `nexo:物品ID` |
| MMOItems | `mmoitems:类型:物品ID` |

写 `custom-item:` 后不用再写 `material:`，材质会从自定义物品自动获取。
卖出时会按完整物品匹配，不会把普通物品当成自定义物品收走。

> 对应插件没装、或者物品 ID 写错时，这个商品会加载失败并在控制台提示，不会退化成普通原版物品。

### 写法三：展开写（需要 lore 等复杂项时）

```yaml
items:
  golden_apple:
    buy: 78
    stock: 200
    limit: 3
    lore: '&7限量供应'
```

### 写法四：列表

```yaml
items:
  - STONE 12
  - OAK_PLANKS 22 stock=500
```

## 商品字段大全

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `material` | 否 | 用 key 当材质 | 只有 key 不是材质名时才需要写，如 `my_bread: { material: BREAD }` |
| `custom-item` | 否 | — | 自定义物品来源，如 `itemsadder:ns:id` / `nexo:id` / `mmoitems:TYPE:ID` |
| `discount` | 否 | 1 | 折扣倍率，`0.8` = 八折 |
| `discount-start` | 否 | 立即 | 折扣开始，如 `2026-12-01 00:00` |
| `discount-until` | 否 | 永久 | 折扣截止，如 `2026-12-31` 或 `2026-12-31 23:59` |
| `vip-price` | 否 | — | VIP 买价，拥有 `vip-permission` 的玩家生效 |
| `vip-permission` | 否 | `xshop.vip` | VIP 价格需要的权限 |
| `buy` | 购买菜单必填 | 0 | 单个买入价 |
| `sell` | 收购菜单必填 | — | 单个卖出价 |
| `slot` | 否 | 自动 | 放在第几格（0~35），不写就按顺序排列 |
| `stock` | 否 | 不限量 | 限量供应，如 `stock: 500` |
| `restock` | 否 | 不补 | 每次自动补货数量，如 `restock: 10` |
| `restock-interval` | 否 | 不补 | 补货间隔秒数，如 `restock-interval: 3600` |
| `dynamic` | 否 | false | 开启动态价格 |
| `limit` | 否 | 不限购 | 每人每天限购几个（购买菜单） |
| `sell-limit` | 否 | 按价格分档 | 每人每天限卖几个（收购菜单） |
| `currency` | 否 | 全局默认 | 单独指定货币，如 `points` |
| `permission` | 否 | 无 | 购买这个商品需要的权限 |
| `lore` | 否 | 无 | 自定义说明文字 |
| `glow` | 否 | false | 图标是否发光 |
| `custom-model-data` | 否 | 0 | 自定义模型数据 |

> **价格都是「单个」的价格**，不再有「一份多少个」的概念。

### 折扣和 VIP 价格

两种玩法，先想清楚要哪一种：

| 需求 | 用什么 | 谁享受 |
|---|---|---|
| 限时活动，所有玩家打折 | `discount` | 所有人 |
| 会员专属价 | `vip-price` | 有 `xshop.vip`（或自定义权限）的人 |

**限时折扣（所有人）**

```yaml
items:
  diamond:
    buy: 200
    discount: 0.8                  # 八折 → 160
    discount-until: '2026-12-31 23:59'
```

**会员专属价**

```yaml
items:
  diamond:
    buy: 200
    vip-price: 150                 # 会员价
    vip-permission: xshop.vip      # 不写默认就是 xshop.vip
```

简写也行：

```yaml
items:
  diamond: 200 vip-price=150
```

然后给会员组加权限（LuckPerms）：

```
/lp group vip permission set xshop.vip true
```

规则：

- 折扣同时作用于买价和卖价
- VIP 价只作用于**买价**，并且优先于折扣和动态价格
- `vip-price` 是绝对价格，不是百分比；想让全部商品打九折只能逐个算好会员价
- 不写 `discount-until` 就是长期有效
- 改完 `/shop reload`，会员在商品说明里会看到「VIP 专享价」

常见坑：

- 给了 `vip-price` 但没给玩家 `xshop.vip` 权限 → 玩家仍按原价买
- 自定义了 `vip-permission`，却还在给 `xshop.vip` → 权限对不上


## 完整示例

### 购买商店

```yaml
id: basic
name: '基础物资'
icon: GRASS_BLOCK
type: BUY

desc:
  - '&7食物、燃料、矿物等日常物资'

items:
  # 普通商品一行一个
  cobblestone: 0.5
  bread: 0.38

  # 限量 + 动态价格 + 限购
  diamond:
    buy: 200
    stock: 300
    dynamic: true
    limit: 16

  # 用点券买
  netherite_ingot:
    material: NETHERITE_INGOT
    currency: points
    buy: 50
```

### 收购商店

```yaml
id: recycle
name: '材料回收'
icon: HOPPER
type: SELL          # ← 关键：SELL 表示收购

desc:
  - '&7把你多余的材料卖给商店'

items:
  cobblestone: 0.02
  diamond:
    sell: 25
    sell-limit: 8   # 单独限制每天只能卖 8 个
```

## 库存系统

商品写了 `stock` 才启用库存：

```yaml
diamond:
  buy: 200
  stock: 300        # 初始库存 / 最大库存都是 300
```

- 每买走 1 个，库存 -1
- 玩家卖回给商店，库存 +1
- 库存为 0 时显示「已售罄」
- 库存数据存进数据库，重启不丢

## 自动补货

自动补货是**单个商品**单独配置的，不会全局生效。

### 最小写法

```yaml
emerald:
  buy: 100
  stock: 300              # 必须有库存上限
  restock: 10             # 每次补 10 个
  restock-interval: 3600  # 每 3600 秒（1 小时）补一次
```

也可以一行写：

```yaml
emerald: 100 stock=300 restock=10 restock-interval=3600
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `stock` | 是 | 最大库存；没有库存上限就不补货 |
| `restock` | 是 | 每次补多少个 |
| `restock-interval` | 是 | 两次补货之间隔多少**秒** |

### 实际运行方式

- 插件每 **60 秒**检查一次所有商品
- 某个商品距离上次补货已经超过 `restock-interval`
- 且当前库存小于 `stock`
- 就把库存增加 `restock`，但不会超过 `stock`

时间线示例：

```text
00:00  库存 300 / 300
00:10  玩家买走 50 → 库存 250
01:00  插件检查，距上次补货超过 1 小时 → 补到 260（+10）
02:00  再补到 270
...
```

### 常用配置

**每小时补 10 个，最多 300**

```yaml
diamond:
  buy: 260
  stock: 300
  restock: 10
  restock-interval: 3600
```

**每小时直接补满**

```yaml
emerald:
  buy: 100
  stock: 200
  restock: 200
  restock-interval: 3600
```

**每 10 分钟补 5 个**

```yaml
golden_apple:
  buy: 78
  stock: 100
  restock: 5
  restock-interval: 600
```

**少量多次补货，适合活动商品**

```yaml
nether_star:
  buy: 5000
  stock: 10
  restock: 1
  restock-interval: 1800
```

### 跨服行为

MySQL 模式下，补货时间记录在数据库里：

- 多个服同时在线也不会重复补货
- 服务器重启不会重置补货计时
- 其他服会自动刷新到最新库存

SQLite 单服模式：

- 补货计时在内存里
- 重启后计时会重置，可能提前补一次
- 只适合单服

### 和手动改库存的关系

管理员执行：

```text
/shop stock <分类> <商品id> <库存>
```

只是设置当前库存，不会重置自动补货计时。

如果手动把库存补满，自动补货会跳过，直到库存再次低于上限。

### 不生效怎么排查

| 现象 | 检查 |
|---|---|
| 完全不补货 | 是否同时写了 `stock`、`restock`、`restock-interval` |
| 间隔写 30 秒还是很久才补 | 插件每 60 秒检查一次，最小实际间隔约 60 秒 |
| 库存满了不补 | 正常，满库存会跳过 |
| 重启后提前补了 | SQLite 单服模式计时在内存，重启会重置 |
| 多服重复补 | 必须用 MySQL；SQLite 每个服各自计时 |
| 改了没反应 | 执行 `/shop reload` |

### 验证方法

1. 把商品库存改成较低值
2. 等待一个 `restock-interval` + 最多 60 秒
3. 用 `/shop info <分类> <商品id>` 看库存
4. MySQL 模式可以查 `shop_stock.last_restock` 确认补货时间

## 动态价格

```yaml
quartz_block:
  buy: 6
  stock: 500
  dynamic: true     # 一个开关就够了
```

规则：库存越少价格越贵，涨跌范围由 `config.yml` 的 `dynamic.min/max` 控制。

价格公式在 `config.yml` 里选：

```yaml
dynamic:
  formula: linear      # 线性（默认）
  # formula: step      # 阶梯：每 1/steps 库存涨一档
  # formula: exponential   # 指数：越接近售罄涨得越猛
  steps: 5             # 仅 step 公式有效
```

改动不会影响已经写死的固定价格商品（没开 `dynamic: true` 的商品）。

## 活动商店

给整个分类加上开放 / 结束时间，到点自动上架、到点自动消失：

```yaml
id: spring_event
name: '春节活动'
icon: FIREWORK_ROCKET
type: BUY
open-from: '2026-02-01 00:00'
open-to: '2026-02-20 23:59'

items:
  firework_rocket: 5
```

- 时间格式：`yyyy-MM-dd HH:mm`（服务器本地时区）
- 未到 `open-from` 或过了 `open-to`，玩家在主菜单、分类列表、命令里都看不到这个商店
- 直接访问会提示「这个活动商店还没开放或已经结束」
- 改完执行 `/shop reload` 立即生效

## 每日限购

```yaml
golden_apple: 60 stock=100 limit=3
```

或者展开写：

```yaml
golden_apple:
  buy: 60
  limit: 3          # 每人每天最多买 3 个
```

## 每日限卖

不写 `sell-limit` 时按价格自动分档。想单独设定：

```yaml
dirt:
  sell: 0.01
  sell-limit: 1000   # 每天最多卖 1000 个

sand: 0.02            # 不展开也可以，自动按价格分档
```

## 权限控制

```yaml
id: vip_shop
name: 'VIP 商店'
icon: DIAMOND
type: BUY
permission: myshop.vip      # 整店需要权限

items:
  netherite_ingot:
    buy: 1200
    permission: myshop.vip.netherite   # 单个商品需要权限
```

没权限的商品**不会显示**在界面里。

## 常见错误

| 现象 | 原因 |
|---|---|
| 商店不出现 | `type` 写错 / yml 缩进错误 |
| 价格显示 0 | `BUY` 商店写成 `sell:`，或 `SELL` 商店写成 `buy:` |
| 商品显示英文 | 材质 key 拼错，或者没这个材质 |
| 改完没生效 | 忘了 `/shop reload` |

### 检查 YAML 缩进

YAML 对缩进极其敏感，**只能用空格，不能用 Tab**。

```yaml
# ✅ 正确
items:
  cobblestone: 0.5

# ❌ 错误（Tab 缩进 / 层级不对）
items:
	cobblestone: 0.5
```
