# 交易记录与日报

管理员排查刷钱、了解经营情况用的功能。

---

## 一、交易记录

每一笔买 / 卖都会记录下来。

### 记录了什么

| 字段 | 说明 |
|---|---|
| 时间 | 精确到秒 |
| 玩家 | 玩家名 + UUID |
| 商店 / 商品 | 商店 id、商品 id、商品中文名 |
| 买 / 卖 | 方向 |
| 数量 | 本次交易多少个 |
| 单价 / 总价 | 单价 × 数量 = 总价 |
| 管理员标记 | 该玩家是否拥有 `xshop.admin` |

### 存到哪里

**1）文本日志**（始终写）

```
plugins/XingXingShop/logs/transactions-2026-10-02.log
```

一行一笔，可以用记事本 / Excel 打开。带 `[管理员]` 后缀的是管理员的交易。

**2）数据库**（`config.yml` 的 `database.type`）

| 值 | 说明 |
|---|---|
| `sqlite` | 默认。零配置，数据存在 `plugins/XingXingShop/transactions.db` |
| `mysql` | 跨服共享，需要填 `database.mysql` 下的连接信息 |
| `none` | 不写数据库，只用文本日志 |

MySQL 配置示例：

```yaml
database:
  type: mysql
  mysql:
    host: localhost
    port: 3306
    database: minecraft
    username: root
    password: '你的密码'
```

> 数据库要先自己建好（例如 `CREATE DATABASE minecraft DEFAULT CHARSET utf8mb4;`），
> 表由插件自动创建。`url` 留空即可，插件会自动拼连接地址。

### 跨服（多服共用一个 MySQL）

把**每个服务器**的 `database.type` 都改成 `mysql`，并填**同一个数据库**即可。

- 交易 / 库存 / 限购 / 个人日报投递记录全部共享
- 购买时库存和限购用 MySQL 事务原子扣减，**多服同时买也不会超卖**
- 各服每 5 秒自动从数据库刷新库存显示，交易时以数据库实时结果为准
- 不需要额外装 Redis / MQ 之类的中间件
- SQLite 只适合单服，改成 MySQL 才会启用跨服逻辑

在 `transactions.db` 里一共有三张表：

| 表 | 存什么 |
|---|---|
| `shop_transaction` | 每笔交易 |
| `shop_stock` | 每个限量商品的库存 / 销量 |
| `shop_limit` | 每个玩家每天的限购 / 限卖计数 |

也就是说，**交易、库存、限购三类数据都进数据库**。文本日志和 `stock.yml` / `limits.yml`
只在数据库不可用时作为兜底；第一次从旧版本升级时会自动把旧文件数据迁移进数据库。

> 数据库写入走**独立单线程队列**，不阻塞主线程，也不会因为并发抢锁而卡住。SQLite 已开启 WAL 模式。

### 游戏内查询

```
/shop log                  # 最近交易（第一页）
/shop log Steve            # 只看玩家 Steve
/shop log Steve 2          # Steve 的第 2 页
```

### 管理员交易不计入统计

有 **`xshop.admin` 权限**的玩家，其交易会照常记录（日志和数据库里都有，并带 `[管理员]` 标记），
但在**日报统计和 PlaceholderAPI 统计中会被自动跳过**。

这样做是因为管理员测试商店时会大量交易，会污染统计数据。

> 判定方式是实时看权限，不是看名字。临时给某人 `xshop.admin` 后他的交易也会被标记。

## 二、可疑交易提醒

`config.yml`：

```yaml
log:
  alert:
    enabled: true
    rate-limit: 20     # 10 秒内超过 20 笔 → 提醒
    amount: 10000      # 单笔金额超过 10000 → 提醒
```

触发时会给**所有在线且拥有 `xshop.admin` 权限的玩家**发消息，同时写一条 `WARNING` 到控制台。

- 把 `rate-limit` 或 `amount` 设成 `0` 可单独关闭该项检测
- 关掉整个提醒：`enabled: false`

## 三、每日日报

### 开启与时间

```yaml
log:
  report:
    enabled: true       # 总开关
    hour: 0             # 每天 0 点发（24 小时制，服务器本地时间）
    range: yesterday    # yesterday = 汇总前一天；today = 汇总当天到现在
    notify-in-game: true
    write-file: true
```

### 日报内容

- 交易笔数、买入 / 卖出数量
- 玩家支出 / 玩家收入 / 净流入
- 最活跃玩家 Top 5（按交易额）
- 热门商品 Top 5（按件数）
- 可疑提示：某个玩家交易额占比过高时给出提示

### 日报存到哪

```
plugins/XingXingShop/reports/2026-10-02.log
```

**一天一个文件**，方便归档查阅。

### 手动查看 / 生成

```
/shop report                # 默认看昨天
/shop report today          # 今天到现在
/shop report yesterday      # 昨天
/shop report week           # 最近 7 天
/shop report month          # 最近 30 天
/shop report 2026-10-01     # 指定日期
/shop report list           # 列出所有已生成的日报文件
```

关掉日报功能后 `/shop report` 会提示功能已关闭（命令仍在，只是不可用）。

## 四、个人日报（给玩家）

除了全服日报，每个玩家还能看**自己的**交易汇总。

### 内容

- 自己买入 / 卖出的笔数、数量、金额
- 净收益
- 全服活跃排名（第几名 / 共几人）
- 自己买得最多、卖得最多的前三件商品

### 查看

```
/shop myreport              昨天
/shop myreport today        今天到现在
/shop myreport week / month 最近 7 / 30 天
/shop myreport 2026-10-01   指定日期
```

### 自动推送

```yaml
log:
  report:
    player:
      enabled: true          # 总开关
      notify-in-game: true   # 每天定时推送给在线玩家
```

**统一时间**触发（`log.report.hour`，默认 0 点）：

- 在线玩家 → 立即收到
- 离线玩家 → **下次上线时补发**（从上一次收到那天起补到昨天）
- **只保留 1 个月**，超过 30 天的不再补
- 投递进度记录在数据库 `shop_report_seen` 表，补过不重复

到点后自动发给每个在线玩家；关掉推送也能用命令手动查。

> 同样地，管理员的交易不会算进个人日报。

---

## 五、关闭与清理

- 不想记录任何交易：`log.enabled: false`
- 想删旧数据：直接删 `logs/`、`reports/` 下的旧文件；数据库用 SQLite 工具删 `transactions.db` 里的旧记录即可
- 数据库文件损坏：删掉 `transactions.db`，重启会自动重建（会丢历史记录）
